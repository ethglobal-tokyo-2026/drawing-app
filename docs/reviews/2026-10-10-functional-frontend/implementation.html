Decisions and corrections

These summarize every recorded ruling, including the rejected proposal and later corrections. They describe the current scope and its tradeoffs.

  1. Account scope. Protected logout, chat-menu state, late profile updates, and background profile refresh were included so direct calls cannot bypass account checks. Tradeoff: a larger authentication test surface; explicit anonymous sign-in remains available.
  2. Background cookies. Account-bound profile refresh no longer issues a session cookie, preventing its delayed response from overwriting another login. Tradeoff: background updates no longer extend session expiry.
  3. 401 recovery: initial rejection, subsequently authorized. Automatic approval review initially rejected replacing silent post-ready recovery with explicit Reload as broader than the authorized plan. The user subsequently delegated this choice; decision 24 records the accepted recommendation and its implementation. Tradeoff: one explicit action after expiry; initial sign-in and ordinary wallet retries remain unchanged.
  4. Creation lane. Creation work runs in an isolated worktree with one implementer. Tradeoff: commits and changed interfaces require integration and rechecking; task reviews remain separate.
  5. Board work before the 401 decision. Board persistence continued against the reviewed immutable-account client while the separate recovery decision was pending. Tradeoff: account teardown required renewed checks after that decision changed; those checks now pass. This does not establish release readiness on untested devices.
  6. Saved-drawing reconciliation. Recovery gained explicit checking, failure with Retry, and resolved states so failed Seal-status reads stay visible without discarding ink. Tradeoff: a larger component contract and retry tests. The initial rule that all unknown outcomes stay locked was later narrowed by the historical-ticket correction below.
  7. Active board gestures. A read-only gesture-position accessor preserves moves still held in the DOM when reads or acknowledgements arrive. Tradeoff: another hook contract and stale-position tests; the save store does not own DOM state.
  8. Identity lane. Wallet and identity work runs in another isolated worktree using the account-client contract. Tradeoff: another integration pass; heavy checks and browser servers remain serialized.
  9. Historical-ticket correction. Review found that the initial reconciliation gate could lock a drawing forever after the ticket day changed. A successful read that omits an old sent-Seal ticket now permits explicit abandonment, without calling it unsealed or reusing it. Tradeoff: abandonment forfeits further local use of that ticket. Ink export remains available until discard; failed reads retain Retry, and a fresh ticket still requires explicit Start.
  10. Wallet catalog ownership. Reload copy stays in the Sticker Board catalog where its address/status control is rendered. The unrelated identity catalog was not edited merely to match the planned file list. Tradeoff: a documented file-list correction, with no behavior cost.
  11. G2 assignment. A completed planning agent received its first implementation brief after the agent limit prevented a new seat. Tradeoff: retained planning context, constrained by a new bounded brief and independent review; no second implementer shared a checkout.
  12. Gift contract and G4 dependency. The giver-only PackagedGift change belongs in packaging.ts, so public Gift metadata and shapes.ts were left alone. Sent/maybe-sent recovery preserves identity; G4 owns durable sending and removal of automatic missing-token Take out. Tradeoff: G2 alone is not safe against storage-loss or two-tab sending. Its temporary fallback preserves the returned original recipient.
  13. Current drawing layers. The committed drawing-layers baseline was integrated before further schema/replay work. Reviewed fixes were retained and integration checked independently. Tradeoff: conflict resolution and renewed checks; the entire incoming feature was not audited again.
  14. Conservative cut cleanup. Only the now-unused pixel averaging wrapper was removed after its sole caller changed. The below-threshold fixture was corrected to 59%. Tradeoff: one additional source file for deletion; final-image averaging is unchanged.
  15. Layered replay ownership. Replay preparation must account for original layer/scratch canvases and cached per-fill data, as well as its single active snapshot. A narrow releaseFill operation is approved for preparation. Tradeoff: another ownership operation and layered memory tests; ordinary drawing/undo caching stays intact and no absolute heap ceiling is claimed.
  16. Gift storage warning and attempt ID. A narrow storage-error getter keeps read/save failures visible while server-acknowledged attempts can use memory fallback. Attempt IDs use 32 random bytes without a general identifier abstraction. Tradeoff: one small flow error contract; server state remains authoritative.
  17. Layer panel input boundary. Layer-aware capture dismissal was preserved while panelOpen remains an input-boundary signal. Tradeoff: the combined behavior needs unit/native coverage so held contacts cannot survive panel entry.
  18. Historical layer fixtures. Legacy fixtures remain legacy where they test migration; current engine and saved-session inputs use valid layered steps. Tradeoff: those roles must remain distinct to preserve migration coverage.
  19. Combined platform acceptance. Full browser and iPad checks belong to the final combined branch. Task and integration tests establish their own scoped contracts. Tradeoff: final platform acceptance remains open until that phase.
  20. Back during a visible exit. The requirement to keep Back inside Croquis takes precedence over the plan detail that removed a ticket card registration as soon as leaving began. A real browser regression and narrow correction passed independent review. Tradeoff: the guard may live longer, while one-entry and one-callback behavior must remain intact.
  21. Uncertain storage and authoritative gift recipients. Unknown or unreadable saved-session metadata must enter non-destructive recovery, and resumed Giving must disclose a recipient mismatch before recovery actions. Both follow the accepted preservation and recipient requirements. Tradeoff: narrow recovery contracts, bilingual copy, and new tests; ticket ownership must not be inferred and gifts must not be automatically retargeted.
  22. Historical probe preservation. Original reproduction snapshots retain their audit-era code and failures. A direct lint check against current types fails on those snapshots, including old layer fixtures and out-of-project imports. Application commits passed their hooks and fresh package gates. The documentation-only commit uses separate formatting, link, and current mutation-runner checks instead of application commit hooks. Tradeoff: the archived probes are not current typed tests; run them at the documented audit revision. No application source or configuration is exempted.
  23. Checkout test timing. Fresh browser verification exposed a separate assertion that threw on the temporary Free label before the refreshed yen price arrived. Repair that test with a retrying exact-price assertion, retaining the ticket-count check and failed trace. Tradeoff: one additional test-only correction, affected browser rerun, and independent review; the accepted production fixes and full audit are not reopened.
  24. Explicit Reload after session expiry. The user delegated the remaining recovery choice and accepted the recommendation to stop silent post-ready sign-in. The account subtree closes on expiry, late answers cannot reopen it, and Reload is explicit. Initial bootstrap remains available. Tradeoff: one user action after expiry; in return, a delayed recovery response cannot silently replace a newer login. Real-cookie browser regressions and independent review passed.
  25. Verify Safari on the installed iPadOS 26.5 simulator. The host Safari 27.0.1 driver connects to that simulator but rejects the iPadOS 27 target. Use an explicit device selection and report the observed runtime; do not silently fall back or infer the internal cause. Cost: this run cannot establish iPadOS 27 behavior.
