# Node 24 LTS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the auth server and the REST API on the box on Node 24.21.0 LTS, the Node the repo develops and tests on, and bring every tool and dependency to its latest stable version.

**Architecture:** The root `package.json` pins Node in `devEngines.runtime`, so pnpm runs every script on that exact version. `deploy/install-node.sh` installs the same version on the box under `/usr/local/lib/nodejs/`, next to NodeSource's `/usr/bin/node` (Node 22), which the box's other projects keep. `sticker-auth` and `drawing-api` start from `/usr/local/lib/nodejs/node-24/bin/node`. The API stays one esbuild bundle.

**Tech Stack:** pnpm 12 `devEngines.runtime`, bash, systemd, esbuild, Foundry.

---

## Facts (checked 2026-09-26)

- Node 24 "Krypton" is Active LTS (Maintenance from 2026-10-20, end of life 2028-04-30); newest is 24.21.0. Node 26 becomes LTS on 2026-10-28. Node 22 reaches end of life on 2027-04-30.
- The box (`bawler@195.201.8.147`): Debian 13.7, x86_64, glibc 2.41, passwordless sudo. `/usr/bin/node` is NodeSource `nodejs` 22.22.0 (repo `node_22.x`). `gallery`, `line-of-bugs` and `maw-agent` run it too, each with a better-sqlite3 built for Node 22's ABI (`node_register_module_v127`): with `/usr/bin/node` on 24, each would fail to start at its next restart. Leave it alone.
- `drawing-api` (branch `ship`) runs `/usr/bin/node /srv/drawing-api/server/server.mjs` today. Its better-sqlite3 13.0.3 loads through N-API (`napi_register_module_v1`), so Node 24 needs no reinstall.
- The box has `gpg` but not `gpgv`. With nodejs/release-keys' keyring, `gpg --decrypt` passes 24.21.0's `SHASUMS256.txt.asc` and fails a copy with one checksum digit changed (`BAD signature`, exit 1). `/usr/local/lib/nodejs` (nodejs.org's place for a tarball install) doesn't exist yet.
- pnpm 12 ignores the root `engines.node`. `devEngines.runtime` with `onFail: "download"` runs every workspace package's scripts on the pinned Node (root `node_modules/.bin/node` too, so the git hooks) and records its per-platform integrity in `pnpm-lock.yaml`.
- `pnpm update --latest` skips versions younger than `minimumReleaseAge` (3 days): it takes turbo 2.11.3, not 2.11.4.
- `packages/db/src/migrate.ts` ends with `if (import.meta.main) migrateDatabase();`. `import.meta.main` is new in Node 24, and in a bundle it's true, so on Node 24 the API bundle would migrate twice on start (esbuild 0.28.2: "migrate" printed twice; with `define: { "import.meta.main": "false" }`, once).

- [ ] **Step 1: Create `deploy/install-node.sh`** (then `chmod +x deploy/install-node.sh`)

```bash
#!/usr/bin/env bash
# deploy/install-node.sh: put the Node that package.json pins (devEngines.runtime) on the box, next to the box's own
# /usr/bin/node, NodeSource's Node 22, which the box's other projects still run on.
#
#   ./deploy/install-node.sh
#
# deploy.sh and deploy-api.sh run it. sticker-auth and drawing-api start from /usr/local/lib/nodejs/node-24/bin/node,
# so when the link moves to a newly pinned version, both restart. A new major needs a new link: change node-24 in
# both units and in deploy-api.sh, and esbuild's target in apps/api/scripts/build.ts.
set -euo pipefail

ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
if [ -f "$ROOT/deploy/.env" ]; then
  # shellcheck source=/dev/null
  . "$ROOT/deploy/.env"
fi
TARGET="${DEPLOY_TARGET:?set DEPLOY_TARGET (user@host) in deploy/.env}"
VERSION="$(node -p "require('$ROOT/package.json').devEngines.runtime.version")"

# One SSH connection for every ssh below: the box resets bursts of new ones.
SSH_OPTS=(-o ControlMaster=auto -o "ControlPath=$HOME/.ssh/cm-deploy-%C" -o ControlPersist=60)
ssh() { command ssh "${SSH_OPTS[@]}" "$@"; }

ssh "$TARGET" "bash -s -- '$VERSION'" <<'BOX'
set -euo pipefail
version="$1"
dir=/usr/local/lib/nodejs
name="node-v$version-linux-x64"
link="$dir/node-${version%%.*}"
if [ ! -x "$dir/$name/bin/node" ]; then
  echo "→ installing $name on the box"
  tmp="$(mktemp -d)"
  trap 'rm -rf "$tmp"' EXIT
  cd "$tmp"
  # Checked as nodejs.org says: a Node releaser signs SHASUMS256.txt. The box has gpg but not gpgv, and a GNUPGHOME
  # of its own keeps the deploy user's keyring out of it.
  export GNUPGHOME="$tmp/gnupg"
  install -d -m 700 "$GNUPGHOME"
  curl -fsSLo keyring.kbx https://github.com/nodejs/release-keys/raw/HEAD/gpg/pubring.kbx
  curl -fsSO "https://nodejs.org/dist/v$version/SHASUMS256.txt.asc"
  curl -fsSO "https://nodejs.org/dist/v$version/$name.tar.xz"
  gpg --batch --quiet --no-default-keyring --keyring "$tmp/keyring.kbx" --output SHASUMS256.txt \
    --decrypt SHASUMS256.txt.asc 2>/dev/null || { echo "✗ no Node releaser signed SHASUMS256.txt" >&2; exit 1; }
  sha256sum --check --ignore-missing --quiet SHASUMS256.txt \
    || { echo "✗ $name.tar.xz doesn't match SHASUMS256.txt" >&2; exit 1; }
  sudo install -d -m 755 "$dir"
  sudo tar --no-same-owner -xJf "$name.tar.xz" -C "$dir"
fi
if [ "$(readlink "$link" || true)" != "$name" ]; then
  sudo ln -sfn "$name" "$link"
  sudo systemctl try-restart sticker-auth drawing-api
  echo "↻ $link → $name: restarted sticker-auth and drawing-api"
fi
BOX
```
