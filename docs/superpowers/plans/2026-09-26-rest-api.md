# REST API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build every route of the REST API contract in `apps/api`, test-first, on the `packages/db` schema.

**Architecture:** `createApp(deps)` mounts one router per route group at `/api`. Every outside service sits behind `AppDeps`, so route tests run through `createTestApp()` on an in-memory database with fakes. Task 1 adds the views every group shares; then each route group is one task that owns its router file, its own folder and its tests, so Tasks 2–8 run in parallel.

**Tech Stack:** Hono 4.13, @hono/zod-validator 0.9, zod 4, drizzle-zod 0.8, Drizzle ORM 0.45 on better-sqlite3, viem 2.56.9 (keccak256), vitest 5, TypeScript 7, Node 24 (runs the TypeScript directly).

**Contract (binding):** `docs/database-schema-and-rest-api.md`, section "REST API", at commit 362a4cd. On a branch that predates it, read it with `git show 362a4cd:docs/database-schema-and-rest-api.md`. It fixes every route, request, response, error code and convention; each task names its section and doesn't restate it. If a rule can't work, stop and report it instead of diverging.

**Schema:** `docs/superpowers/plans/2026-09-26-database-schema.md` gives the tables, columns, CHECKs, the limits in `@drawing-app/db` (`MAX_TIME_USED_S`, `GIFT_EXPIRY_MS`, `MAX_HITS`, `MAX_PEAK_TIER`, `MAX_PEAK_MULT`) and the test harness `@drawing-app/db/testing` (`createTestDb`, `insertUser`, `insertSticker`, `packGift`, `newId`, `bytes32`, `refusal`).

**Foundation (built before this plan, from commit cd0ed61):** `apps/api` with

- `src/deps.ts`: `AppDeps`: `db`, `sessionSecret`, `clock`, `ids`, `line`, `images`, `mint` (a stub), `giftChain` (`null` means the mock chain), `smartWallets`, `sui`;
- `src/errors.ts`: `ErrorBody`, `apiError`, and the zod-validator hook that answers 400 `invalid_request`, naming the field;
- `src/session.ts`: `requireSession`, `AppEnv`, `setSessionCookie`;
- `src/shapes.ts`: the `Person` and `Me` schemas, types and mappers;
- `src/routes/{session,tickets,stickers,stickerBoards,gifts,gratitude,explore}.ts`: one empty factory, `(deps) => new Hono<AppEnv>()`, each already mounted by `createApp` in `src/app.ts`;
- `src/testing/`: fakes and `createTestApp()` with `signInAs(userId)`;
- `packages/db/package.json`: the `"./testing": "./src/testDb.ts"` export;
- `apps/api/package.json`: every dependency the tasks use. That includes `viem` 2.56.9 (keccak256, Tasks 4 and 6) and `@drawing-app/sticker-chain` (`createGiftClaim`, Task 6), besides Hono, zod, drizzle-zod and drizzle-orm.

**Not in this plan:** the worker (mint retries, deposit re-checks, claims, rejects, returns, LINE pushes); switching the frontend to Hono's client; deploying the API; the server-side gratitude recount, which waits for the Mini-game's combo engine to be shareable.

### Decided during the build

- **Mount points:** routers are mounted per group (`/api/stickers`, `/api/sticker-boards`, `/api/gifts`, `/api/gratitude`), not with full paths at `/api`. Session, tickets and Explore keep full paths at `/api`.
- **Views:** `toSticker` and `loadStickers` take `urls` (`deps.images.urls`). The Sticker, Gift and Gratitude schemas live only in `views.ts`. The views take `Db`, so code inside a transaction needs a type that accepts both.
- **Session:** deletion also clears the handle.
- **Tickets:**
  - built to the earlier rules: 4:00 in the person's zone, and free and paid tickets;
  - the contract now says daily and reserve tickets, with the day at midnight Tokyo, and that update is in progress;
  - `GET /api/ticket-quote` came into the contract with the ticket shop (bae3bb6), after this plan; no task covers it yet;
  - an unverified payment answers 500 `internal_error`, not `internal`.
- **Stickers:**
  - the timelapse is optional and stored as sent, checked only against its size limit, and its GET is put off;
  - a failed mint still answers 201;
  - `metadata_uri` is `{stickerId}.json` beside the PNG;
  - the outline pattern `/^M[-\d. LZ]*Z$/` hasn't been checked against what the app sends.
- **Boards:**
  - someone else's board shows `openGift` and `seenAt` as null;
  - `givenTo` is added, per 9822ef7;
  - given and received count only received gifts.
- **Gifts:**
  - the deposit validates `txHash` but can't use it;
  - a preview of an unknown token is 404 even from a group chat;
  - preview and receive follow 9822ef7: `liffContextType`, the sticker only when receivable, `group_chat` first, and `terms_accepted_at`;
  - on the escrow chain only, a deposit that lands after a take-out and repackage answers 500. That's for the worker.
- **Typed client:** `apps/api/src/client.ts`, exported as `@drawing-app/api/client`, is on main (98cb4dd).

## Contract additions

Rules this plan decides that the contract doesn't state, for the contract doc.

- **All routes:** every `created_at` stays the database's, a sticker's seal time included.
- **All routes:** a gift ID or Gift Claim Token that isn't `0x` and 64 lowercase hex digits is 400 `invalid_request`. Person and sticker IDs aren't format-checked: an unknown one gets its route's 404.
- **Types:** `Gratitude.peakTier` is an integer from 0 to `MAX_PEAK_TIER` in the server's types. The JSON is the same as `0 | 1 | 2 | 3 | 4`.
- **`Me.newStickerCount`:** stickers you still hold whose placement has no `seen_at`.
- **`Me.unseenGratitudeCount`:** gratitude on gifts you gave that you haven't watched.
- **Session:** a handle's 32 characters are counted as code points. "Ignoring letter case" folds ASCII letters only, as SQLite's `lower` does.
- **Session:** a first sign-in takes the LINE name as the handle only if it passes the handle rules and nobody has it; otherwise `needsHandle`.
- **Session:** `POST /api/me/handle` can change a handle at any time.
- **Session:** LINE's reason for refusing a token goes to the server log, never the response.
- **Session:** `DELETE /api/me` sets `deleted_at` and clears the three LINE columns. It keeps the handle (reserved), the smart wallet, stickers and gifts. Signing in again with the same LINE account makes a new person.
- **Tickets:** `txDigest` is a base58 Sui digest of 43–44 characters, and `paidMist` is decimal digits.
- **Tickets:** `paidMist` is recorded as sent: there's no price check while the payment is a mock.
- **Tickets:** a payment that fails the Sui check has no code; it's 500 `internal`, which the mock can't reach.
- **Stickers:** an oversized seal body is 400 `invalid_request`, in `ErrorBody` JSON.
- **Stickers:** the server computes the content hash from the uploaded PNG and stores image files write-if-absent, so a second seal of the same PNG uses the first seal's files.
- **Stickers:** `png` and `mask` must be `width` × `height`. `spec`, `rim` and `flat` are checked only as PNGs. The size limits are in Task 4.
- **Stickers:** the mint step writes the NFT metadata JSON at `metadata_uri` before minting; sealing doesn't write it.
- **Stickers:** the Transfer Trail lists `received` gifts only.
- **Stickers:** any signed-in person can read any sticker's detail and timelapse.
- **Boards:** someone else's board lists only their on-board stickers, given silhouettes included, with `openGift` and `seenAt` null. Your own lists every sticker in tray order.
- **Boards:** `me` works for `:userId` on user stats too.
- **Boards:** the placement PATCH works on any sticker that ever reached you, held or given.
- **Boards:** `seen` ignores ids that aren't in your tray, and takes at most 500 at once.
- **User Stats:** `bestCombo` is over the combos you sent.
- **User Stats:** `mostGratitudeInADay` sums your part (the giver's part, plus the Original Artist Gratitude Share) per ticket day in your zone.
- **User Stats:** a best with nothing behind it yet is 0.
- **Giving, mock chain:** a take-back's reject and a receive's claim land at once (`rejected`, `claimed`), like the deposit.
- **Giving, escrow chain:** a giver without a smart wallet has no code; it's 500 `internal`.
- **Giving:** a deposit report for a gift already past `missing` answers the gift as it is.
- **Giving:** `cancelled` on a `sent` gift leaves it `sent`.
- **Giving:** a second take-out is `gift_closed`.
- **Receiving:** a `packed` gift can be received, since the message can go out while the picker never reports back.
- **Receiving:** refusals come in this order: `group_chat`, `gift_not_found`, `own_gift`, `already_received`, `taken_back`, `gift_returned`, `gift_expired`, `not_deposited`. The preview's `refusal` follows the same order, without `group_chat`.
- **Gratitude:** the Original Artist Gratitude Share is `floor(total × 20%)`.
- **Gratitude:** replay bounds. Running positions stay within 0–10000, and ms steps are ≥ 0. The hits' time fits in `durationMs`. Counted touches are at most `hits`, and exactly `hits` for a tap combo. `switchedAtHit` is null exactly for tap combos. `endReason` `sent` comes only with 1 hit.
- **Gratitude:** `total` isn't checked against the hits until the server recount exists.
- **Gratitude:** a body over 64 KiB, the most `keepalive` carries, is `invalid_request`.
- **Gratitude:** the same `idempotencyKey` from someone else is `gratitude_already_recorded`.
- **Gratitude:** any signed-in person can read a gratitude and its replay.
- **Gratitude:** `seen` keeps the first time it was watched.
- **Explore:** each leaderboard lists at most 10 people with a value above 0, highest first, ties A to Z by handle.
- **Explore:** the longest-streak board ranks current streaks, each counted in the person's own zone.
- **Explore:** deleted accounts appear on no leaderboard and in no search.
- **Search:** one leading `@` is dropped from the query, and letter case is folded for ASCII only.

## Rules for every task

- **Routers:** each factory returns one chained expression, `new Hono<AppEnv>().get(…).post(…)`, so Hono's RPC types reach `AppType`. Paths are full (`/tickets/spend`); `createApp` mounts every router at `/api`. Register a static path before a parameter path that could match it (`/gratitude/unseen` before `/gratitude/:giftId`).
- **Sessions:** `requireSession` first on every route except `POST /api/session`.
- **Validation:** every path parameter, query and body goes through `zValidator` with the foundation's hook. Build request schemas from the tables with drizzle-zod (`createInsertSchema(table, refinements).pick(…)`) where a field is a column, with the table's CHECK ranges as refinements. A contract code more specific than `invalid_request` (`handle_invalid`, `pack_unknown`, `replay_invalid`) comes from the handler's own check after a looser schema, or from a hook that maps that field to its code.
- **Responses:** exactly the contract's shapes. Shared ones come from `src/shapes.ts` and `src/views.ts`; a group's own shapes (`Tickets`, `UserStats`, `BoardSticker`, `Explore`…) are zod schemas in its folder, composed from those and from `createSelectSchema(table)` fields. Tests parse every success body with its schema: that is the contract check.
- **Refusals:** `apiError` with the contract's status and code, and a detail that says what failed and for which item.
- **Transactions:** a route that reads and then writes does both in one `deps.db.transaction((tx) => …, { behavior: "immediate" })`. better-sqlite3 transactions are synchronous: await outside services (files, chain, mint, LINE, Privy, Sui) before or after, never inside.
- **Time:** every time a route sets or compares comes from `deps.clock`; `created_at` is always the database's. Tests that need a row on a given day insert it with `createdAt`, and keep the fake clock near the real time, since CHECKs like `gifts_expiry` compare against the database's clock.
- **Tests:** `createTestApp()` and `signInAs(userId)`; rows from `@drawing-app/db/testing` and `src/testing/rows.ts`; limits and rules from named constants (`@drawing-app/db`'s limits and the task's own), never copied numbers. Every test must fail when the behavior it names breaks.
- **Scope:** add no dependency (the foundation installed them all) and edit no file outside the task's list. Tick the task's checkboxes as you go.
- **Before each commit:** the task's tests, then `pnpm --filter @drawing-app/api typecheck && pnpm --filter @drawing-app/api lint`, each exiting 0. The pre-commit hook formats staged files.

```ts
import { gifts, gratitude, stickerPlacements, stickers } from "@drawing-app/db";
import { insertSticker, newId, type TestDb } from "@drawing-app/db/testing";
import { eq } from "drizzle-orm";
import { gzipSync } from "node:zlib";

/** Inserts a sticker the way sealing leaves it: held by its Original Artist, in their sticker tray. */
export function insertSealedSticker(
  db: TestDb,
  artistId: string,
  values: Parameters<typeof insertSticker>[2] = {},
): string {
  const stickerId = insertSticker(db, artistId, values);
  db.insert(stickerPlacements).values({ userId: artistId, stickerId }).run();
  return stickerId;
}

/** Marks a gift received by `receiverId` with its claim landed, and hands them the sticker. */
export function receiveGift(
  db: TestDb,
  giftId: string,
  receiverId: string,
  receivedAt = new Date(),
) {
  const gift = db
    .update(gifts)
    .set({ status: "received", receiverId, receivedAt, escrowStatus: "claimed" })
    .where(eq(gifts.id, giftId))
    .returning()
    .get();
  if (!gift) throw new Error(`There's no gift ${giftId} to receive`);
  db.update(stickers).set({ ownerId: receiverId }).where(eq(stickers.id, gift.stickerId)).run();
  db.insert(stickerPlacements)
    .values({ userId: receiverId, stickerId: gift.stickerId })
    .onConflictDoNothing()
    .run();
  return gift;
}

/** The smallest combo: one tap that sends. */
export const ONE_TAP = { method: "tap", hits: 1, total: 10, peakMult: 1, peakTier: 0 } as const;

/**
 * Records gratitude for a received gift: ONE_TAP, with `values` over it. Its replay is a placeholder,
 * so a test that reads the replay back records through POST /api/gratitude instead.
 */
export function insertGratitude(
  db: TestDb,
  giftId: string,
  values: Partial<typeof gratitude.$inferInsert> = {},
) {
  const row = db
    .insert(gratitude)
    .values({
      giftId,
      idempotencyKey: newId("combo"),
      ...ONE_TAP,
      originalArtistGratitudeShare: 0,
      gameConfigVersion: "test",
      replay: gzipSync(JSON.stringify({ v: 1 })),
      ...values,
    })
    .returning()
    .get();
  if (!row) throw new Error(`Gratitude for gift ${giftId} wasn't recorded`);
  return row;
}
```

/** The hour a ticket day turns over, on the person's own clock. */
export const TICKET_DAY_START_HOUR = 4;

/** `timeZone`'s wall clock at `at`, to the second. */
function wallClock(at: Date, timeZone: string) {
  const parts = new Intl.DateTimeFormat("en-US", {
    timeZone,
    hourCycle: "h23",
    year: "numeric",
    month: "numeric",
    day: "numeric",
    hour: "numeric",
    minute: "numeric",
    second: "numeric",
  }).formatToParts(at);
  const field = (type: Intl.DateTimeFormatPartTypes) =>
    Number(parts.find((part) => part.type === type)?.value);
  return {
    year: field("year"),
    month: field("month"),
    day: field("day"),
    hour: field("hour"),
    minute: field("minute"),
    second: field("second"),
  };
}

/** `YYYY-MM-DD` of a UTC calendar date. */
const dayKey = (utcMs: number) => new Date(utcMs).toISOString().slice(0, 10);

/** `day`, moved by whole calendar days. */
export function addDays(day: string, days: number): string {
  const [year, month, date] = day.split("-").map(Number);
  return dayKey(Date.UTC(year, month - 1, date + days));
}

/** The ticket day `at` falls in: `YYYY-MM-DD` on `timeZone`'s calendar, from TICKET_DAY_START_HOUR. */
export function ticketDay(at: Date, timeZone: string): string {
  const { year, month, day, hour } = wallClock(at, timeZone);
  const date = dayKey(Date.UTC(year, month - 1, day));
  return hour < TICKET_DAY_START_HOUR ? addDays(date, -1) : date;
}

/** How far `timeZone`'s clock runs ahead of UTC at `atMs`, in ms. */
function zoneOffsetMs(atMs: number, timeZone: string): number {
  const w = wallClock(new Date(atMs), timeZone);
  const wallMs = Date.UTC(w.year, w.month - 1, w.day, w.hour, w.minute, w.second);
  return wallMs - Math.floor(atMs / 1000) * 1000;
}

/** When `day` begins: TICKET_DAY_START_HOUR on that date, in `timeZone`. */
export function ticketDayStart(day: string, timeZone: string): Date {
  const [year, month, date] = day.split("-").map(Number);
  const wallMs = Date.UTC(year, month - 1, date, TICKET_DAY_START_HOUR);
  // The offset at a first guess, then at the corrected guess, which settles days the clocks change.
  const guess = wallMs - zoneOffsetMs(wallMs, timeZone);
  return new Date(wallMs - zoneOffsetMs(guess, timeZone));
}

/** When the ticket day after `at`'s begins: the next refill of free tickets. */
export const nextTicketDayStart = (at: Date, timeZone: string): Date =>
  ticketDayStart(addDays(ticketDay(at, timeZone), 1), timeZone);

import { addDays } from "./ticketDays.ts";

/**
 * Consecutive ticket days with a sealed sticker, over the ticket day of each seal. A missed day
 * resets it to 0; `today` isn't missed until it's over. `best` is the highest it has been.
 */
export function streakOf(
  sealDays: Iterable<string>,
  today: string,
): { current: number; best: number } {
  const days = [...new Set(sealDays)].sort();
  let current = 0;
  let best = 0;
  if (days.length === 0) return { current, best };
  const sealed = new Set(days);
  for (let day = days[0]; day <= today; day = addDays(day, 1)) {
    if (sealed.has(day)) best = Math.max(best, ++current);
    else if (day < today) current = 0;
  }
  return { current, best };
}

**Rules** (`src/tickets/tickets.ts`):

**Routes:**

  - Insert `user_id`, `tickets`, `price_yen` (the pack's), `paid_mist`, `tx_digest`, and `verified_at` = now.

**Refusals:**

| Code                      | Status | When                                         |

- Test: `apps/api/src/routes/stickers.test.ts`

**Limits** (`src/stickers/sealForm.ts`): generous bounds, not measured. `makeSticker` caps the sticker's long side at 640 px plus its margin, and the flat sheet at 1100 px.

- `MAX_IMAGE_SIDE = 4096`
- `MAX_IMAGE_BYTES = 4 MiB`
- `MAX_TIMELAPSE_BYTES = 2 MiB` (gzipped)
- `MAX_TIMELAPSE_JSON_BYTES = 16 MiB` (unzipped)
- `MAX_OUTLINE_LENGTH = 200_000` characters
- `MAX_SEAL_BYTES = 32 MiB` (the whole body)

**The form** (`sealForm`, for `zValidator("form", …)`):

- The fields arrive as strings. `ticketUseId` is a positive integer; `timeUsed` runs from 0 to `MAX_TIME_USED_S` (from `@drawing-app/db`); `width` and `height` from 1 to `MAX_IMAGE_SIDE`.
- `outline` is an SVG path of `M`, `L` and `Z` commands and numbers, as `makeSticker` writes it (`/^M[-\d. LZ]*Z$/`), at most `MAX_OUTLINE_LENGTH` characters.
- `png`, `mask`, `spec`, `rim` and `flat` are `File`s of type `image/png`, each at most `MAX_IMAGE_BYTES`.
- `timelapse` is a `File` of at most `MAX_TIMELAPSE_BYTES`. Browsers label gzip inconsistently, so `seal.ts` checks its bytes, not its type.
- A missing or malformed part is 400 `invalid_request`, naming the part.

**`TimelapseV1`** (`src/stickers/timelapse.ts`): a zod schema of the contract's type.

- `v` is `1`. `ink` is two positive integers. `place` is four numbers, with a positive width and height.
- `ops` holds `["brush" | "eraser", color, startMs, points]` and `["fill", color, atMs, x, y]`.
  - `color` is `#` and 6 hex digits; `startMs` and `atMs` are integers ≥ 0.
  - `points` is integers, 4 per point (`length % 4 === 0`).

**Sealing** (`POST /api/stickers`, `src/stickers/seal.ts`):

1. `bodyLimit({ maxSize: MAX_SEAL_BYTES, onError })` from `hono/body-limit` runs first. Over the limit is 400 `invalid_request`, since the contract lists no 413: `onError` answers through `apiError` with the contract's `ErrorBody` JSON, never Hono's default 413 text.
2. **The ticket:** the `ticket_uses` row by `ticketUseId`.
   - None → 404 `ticket_not_found`.
   - Another person's → 403 `ticket_not_yours`.
   - `sticker_id` already set → 409 `ticket_already_used`.
3. **The images:** each starts with the PNG signature (`89 50 4E 47 0D 0A 1A 0A`). The IHDR width and height of `png` and `mask` equal `width` and `height`; `spec` and `rim` are band-sized and `flat` is sheet-sized, so they're only checked as PNGs. A failure is 400 `invalid_request`, naming the part.
4. **The timelapse:** gunzip it with `maxOutputLength: MAX_TIMELAPSE_JSON_BYTES`, `JSON.parse` it, and check it with `TimelapseV1`. A failure is 400 `invalid_request` naming `timelapse`. Store the uploaded gzip bytes as they came.
5. **The content hash:** `contentHash` = viem's `keccak256` of the uploaded `png` bytes, lowercase hex. The server always computes it, and never takes a hash from the client.
6. **The files:** store the five images through `deps.images` under `stickerImageFiles(contentHash)` (Task 1), with type `image/png`, **write-if-absent**. `content_hash` isn't unique, and the PNG's hash names all five files. Anyone can fetch a sticker's PNG from the CDN and seal it again with their own `mask`, `spec`, `rim` and `flat`. So a name the store already holds keeps its file, and the new sticker points at the files that are there. If `deps.images` can't tell whether a name is stored, that's a foundation gap: report it rather than overwrite.
7. **The rows,** in one immediate transaction:
   - Insert `stickers`:
     - `id`: a UUID from `deps.ids`;
     - `number`: the highest `number` + 1;
     - `artist_id` and `owner_id`: you;
     - `time_used`, `width`, `height`, `outline`, `content_hash`;
     - `metadata_uri`: the CDN URL of `{id}.json`.
   - Then update `ticket_uses` to set `sticker_id` where `id` = `ticketUseId`, `user_id` = you and `sticker_id` is null. No row changed means a concurrent seal took the ticket: 409 `ticket_already_used`, and the transaction rolls back.
   - Insert `sticker_placements { user_id: you, sticker_id }` with no spot, which shows NEW.
   - Insert `sticker_timelapses { sticker_id, ops }`.
8. **The mint:** after the commit, call `deps.mint` with the sticker (`id`, `artistId`, `contentHash`, `metadataUri`, `number`, sealed at `created_at`). It's a stub now and mints nothing. When it reports a landed mint, update `token_id` and `mint_tx_hash`.
   - The NFT metadata JSON at `metadata_uri` (number, image, content hash, size, seal date) is the mint's to write before it mints: nothing reads it until the NFT exists.
   - The stub keeps the comment for the NFT owner.
9. **The answer:** 201 `{ sticker, stickerPlacement }`, from `loadStickers` and `toStickerPlacement` (Task 1), passing the foundation's CDN URL function from `deps.images`.

- Any signed-in person may read any sticker.

**Timelapse** (`GET /api/stickers/:stickerId/timelapse`): `sticker_timelapses.ops` for the sticker; none → 404 `sticker_not_found`. Answer `c.body(ops, 200, { "Content-Type": "application/json", "Content-Encoding": "gzip" })`, the stored gzip bytes as they are.

- In `record.ts`: `ORIGINAL_ARTIST_GRATITUDE_SHARE = 0.2`, and `MAX_GRATITUDE_BODY_BYTES = 64 KiB`, the most a `keepalive` request can carry.

**`ReplayV1`** (`replay.ts`), as a zod schema:

- `v` is `1`. `seed` is an integer from 0 to 2³² − 1. `intensity` runs 0–1.
- `stage` is two positive integers. `durationMs` is an integer from 0 to `MAX_COMBO_MS`.
- `endReason` is the contract's five. `switchedAtHit` is an integer ≥ 0, or null.
- `hits`: integers, 4 per touch. `strokes`: arrays of integers, 3 per sample (ms, x and y). `shakes`: integers, 2 per reversal.
- Refinements over the running values. Each of these follows from the one before, so sum them in order:
  - every ms step is ≥ 0, and the hits' steps add up to at most `durationMs`;
  - x and y stay within 0 to `STAGE_UNITS`, for the touches and for each stroke;
  - `counted` is 0 or 1, and a shake's direction is 1 or −1.

**`RecordGratitude`:**

- Built with `createInsertSchema(gratitude, …).pick({ idempotencyKey, giftId, method, hits, total, peakMult, peakTier, gameConfigVersion })`, with these refinements:
  - `idempotencyKey`: a UUID;
  - `giftId`: `0x` and 64 lowercase hex digits;
  - `hits`: 1 to `MAX_HITS`; `total` ≥ 0;
  - `peakMult`: 1 to `MAX_PEAK_MULT`; `peakTier`: 0 to `MAX_PEAK_TIER`;
  - `gameConfigVersion`: 1–64 characters.

  It's extended with `replay: ReplayV1`.

- A `superRefine` compares the replay with the body, with each issue's path under `replay`:
  - counted touches ≤ `hits`;
  - a `tap` combo has `switchedAtHit` null and exactly `hits` counted touches;
  - a `stroke` or `shake` combo has `switchedAtHit` set, and at most `hits`;
  - `endReason` `sent` only with 1 hit.
- `total` isn't checked against the hits: that's the server recount's job, which comes later.
- **The hook:** `POST /api/gratitude`'s `zValidator` hook answers 400 `replay_invalid` when the first failing issue's path starts with `replay`, and the foundation's 400 `invalid_request` otherwise, naming the field either way.
- `bodyLimit({ maxSize: MAX_GRATITUDE_BODY_BYTES, onError })` runs first. Over the limit is 400 `invalid_request`, answered through `apiError`.

**Routes:**

- `POST /api/gratitude` (`record.ts`), in one immediate transaction, in this order:
  1. A `gratitude` row with this `idempotency_key`:
     - on a gift you received → 200 `{ gratitude }`, the stored record, whatever this body says;
     - otherwise → 409 `gratitude_already_recorded`.
  2. No gift `giftId` → 404 `gift_not_found`.
  3. The gift isn't `received` → 409 `gift_not_received`.
  4. Its `receiver_id` isn't you → 403 `not_receiver`.
  5. A `gratitude` row for the gift already → 409 `gratitude_already_recorded`. One per gift; the `gift_id` primary key backs it.
  6. **The share:** the Original Artist is `stickers.artist_id` of the gift's sticker. `original_artist_gratitude_share` = `Math.floor(total × ORIGINAL_ARTIST_GRATITUDE_SHARE)` when the Original Artist is neither the giver nor the receiver, and 0 otherwise.
  7. Insert the row, with `replay` = `gzipSync(JSON.stringify(replay))`.
  8. 201 `{ gratitude: toGratitude(row) }`.
- `GET /api/gratitude/unseen`:
  - `gratitude` ⋈ `gifts` where `gifts.giver_id` = you and `seen_by_giver_at` is null, oldest `created_at` first.
