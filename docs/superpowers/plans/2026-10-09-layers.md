# Layers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Up to ten layers on the drawing screen: a layer column under the size rail, per-layer opacity, Lock transparent pixels, Clip to layer below, drag reorder, a selection flash and Pencil-hover magnification. Sealing, the kept drawing and the timelapse carry layers. Drawing stays lag-free.

**Architecture:**

- **Layer state.** A pure layer model (`LayerState`, changed only by `LayerStep`s) sits beside the ops, and both go in one undo history.
- **Ink.** Each layer's ink is a sheet-sized offscreen canvas. Three canvases show the sheet, `below`, current and `above`, plus a wet-stroke canvas for the live brush stroke. One compositing function serves the display, the fill's read, the seal and the timelapse.
- **Undo.** Checkpoints are copy-on-write per layer, under a memory budget.

**Tech stack:** React 19, TypeScript, Canvas 2D, Vitest, Playwright (Chromium and WebKit), Hono with Zod (API), Drizzle with SQLite (db).

**Spec:** `docs/superpowers/specs/2026-10-09-layers-design.md`. Read it first; this plan doesn't repeat its decisions.

**Code in this plan:** the code blocks are the contracts lanes share (types, signatures, schemas). Bodies follow the spec and the behavior lists here. Every task names its tests and the edit that should turn each one red.

### Spike results

**S2, undo (done).** A seeded simulation of a 3-minute sheet (150 strokes on 3 layers) and a 30-minute Kyoto Seika sheet (1,500 strokes and 20 fills on 10 layers), each with layer steps. Measured in replay cost, where a stroke is 1 and a fill 24.

- **No checkpoint policy alone keeps a deep undo short** when a rebuild replays every layer: the worst undo on the 30-minute sheet stays at 1,165–1,888.
- **The fix is to rebuild only the undone step's layer, with each fill's classes kept in memory.** The worst undo then falls to 264–426, and the median deep undo from 473 to 59–101.
- **`CHECKPOINT_COST` stays 24.** At 12, copies made while drawing rise from 83 to 140 for no gain; at 48, the last-10 worst goes from 10 to 47.
- **Thinning is copy-aware:**
  - drop the checkpoint with the lowest (replay gap its removal leaves) ÷ (distance back from the head + `CHECKPOINT_COST`) ÷ (copies it frees);
  - never the one just taken;
  - checkpoints past the head first, the farthest first.
- **The copy budget** is `max(1, LIVE_CANVAS_BUDGET − inked layers − display canvases)`.
- **A load plans its checkpoints first** (O-3): on the 30-minute sheet at a budget of 8, 5 checkpoints and 8 copies, where taking every 24 cost units made 229 checkpoints and dropped 224.
- **Not recommended:** taking checkpoints during a long undo. It makes up to 11–20 full-sheet copies inside one undo.
- **WebKit, headless on this Mac at a noisy load** (not a device): replaying 24 strokes took 3–29 ms, depending on stroke length; a full-sheet copy took 2 ms.

**S1, display and memory (done).** Headed WebKit on this Mac and Safari on the iPad simulator (iOS 26.5), with ten inked layers at an iPhone sheet (11.08 MB a canvas) and the densest sheet (16.80 MB).

- **The three-canvas display is confirmed.** Frames match a stack of ten (p95 17–18 ms while drawing on any layer or dragging opacity), and each canvas is held once: 11.39 MB of GPU memory a canvas, against 23.38 MB for a stack of canvases in the page.
- **No sheet canvas gets `will-change`.** It alone doubles a canvas's memory.
  - `below` and `above` stay at CSS opacity 1, with each layer's opacity drawn in through `globalAlpha`.
  - The current layer's canvas takes its opacity in CSS; that costs nothing extra.
- **Budget: `CANVAS_BYTES_BUDGET` = 224,000,000 bytes**, the lowest reported old-iOS cap. Each sheet canvas counts w × h × 4. The four shown canvases (`below`, current, `wet`, `above`) count twice, from the simulator's 1.04–1.28 copies.
  - At iPhone density with ten inked layers that leaves 3 checkpoint copies; with three inked layers, 10. The undo spike found even 1 copy keeps the worst undo bounded once a layer rebuilds alone.
  - At the densest sheet, ten layers and the display fill the budget with nothing left, so the copy budget may be 0. A checkpoint copy that can't be made is skipped, and undo replays that layer from its start. iPads report higher caps (256–576 MB).
- **The wet lift fits a frame:** 1–2 ms of script for 3 s and 6 s strokes. What it saves is the 11 MB copy at every pen down.
- **The fill reads the composite on a GPU canvas, then calls `getImageData` once.**
  - On a GPU canvas: 1–2 ms for the near box, 2–10 ms for the whole sheet.
  - Drawn into a `willReadFrequently` canvas, as `InkSurface` copies today: 8–37 ms and 96–243 ms.
  - The first read on a page costs 10–25 ms.
- **The flash's build fits a frame:** 3–5 ms of script at quarter scale.
- **Limits:** timings are WebKit on an M5 Max at a load of 22–38, so a phone will be slower. The pre-iOS 17 cap's accounting of display copies is unknown: only iOS 26.5 runs here.

**Undo research (done).** The spike's rule is exponential thinning under a copy budget. Time-travel debuggers keep checkpoints the same way: the gap between checkpoints grows exponentially with distance back (King et al., USENIX 2005: https://www.usenix.org/legacy/events/usenix05/tech/general/king/king.pdf).

- **Not used: Revolve, and online checkpointing** (Wang & Moin; Stumm & Walther). Both optimize one full reversal and assume checkpoints cost nothing to take; here they would take a full-sheet copy per stroke.
- **Change: keep a head window.** Never evict the newest `HEAD_WINDOW` checkpoints (⌈30 / `CHECKPOINT_COST`⌉ + 1 = 3), so undos up to about 30 strokes deep stay short; thin only older ones.
  - In the research's model, at a 3-copy budget (an iPhone with ten inked layers), the window kept the worst shallow undo at 23. The rule alone let it reach 71–113.
  - Deep undos then replay one layer from its start, which the per-layer rebuild bounds.
- **The rule, in order, while copies held exceed the budget:**
  1. checkpoints past the head (only a redo reaches them), the farthest first;
  2. checkpoints older than the window, by the copy-aware score;
  3. the window's oldest.

  The checkpoint just taken is never the one dropped.

- **No undo depth limit.** Procreate keeps 250 steps, Krita 200, MyPaint 40 and Drawpile 30. Here a deep undo's replay is bounded by one layer's ops, so Croquis keeps undo to the start of the sheet, as it does today.

```ts
// canvas/ops.ts
/** The drawing tools. Brush and eraser make strokes; fill makes fills. */
export type Tool = "brush" | "eraser" | "fill";
/** Numbers per point in `StrokeOp.pts`: x, y, width, t. */
export const STRIDE = 4;
/** A layer's number: printed on its chip, kept for life, never reused on a sheet. */
export type LayerId = number;
export interface StrokeOp {
  tool: "brush" | "eraser";
  layer: LayerId;
  color: string;
  pts: number[];
  T: number;
}
export interface FillOp {
  tool: "fill";
  layer: LayerId;
  x: number;
  y: number;
  color: string;
  gap: number;
  T: number;
}
/** Every mark on a layer is one op. */
export type Op = StrokeOp | FillOp;
/** A change to the layers, one undo step each; `tool` names the change. */
export type LayerStep =
  | { tool: "add"; layer: LayerId; at: number; T: number } // at: its index from the back
  | { tool: "delete"; layer: LayerId; T: number }
  | { tool: "move"; layer: LayerId; to: number; T: number }
  | { tool: "opacity"; layer: LayerId; opacity: number; T: number } // 0–100, whole numbers
  | { tool: "lock"; layer: LayerId; on: boolean; T: number }
  | { tool: "clip"; layer: LayerId; on: boolean; T: number }
  | { tool: "clear"; layer: LayerId; T: number };
export type Step = Op | LayerStep;
export const isOp = (step: Step): step is Op =>
  step.tool === "brush" || step.tool === "eraser" || step.tool === "fill";
```
