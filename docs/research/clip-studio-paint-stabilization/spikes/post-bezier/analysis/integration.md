## Reuse and bounds

- `quadratic.ts`: `QuadraticPoints`, `evaluateQuadratic`, `splitQuadratic`, `measureQuadratic`, `sampledQuadraticLength`, `quadraticLength`. These retain addressed instruction-order arithmetic, including fused operations where observed.
- `sampling.ts`: `sampleQuadraticForCorrection(points, density, tStart, tEnd)` uses 4–255 intervals followed by the separately evaluated exact final parameter, so at most 256 points per segment. This is the useful existing segment sampler. Verify the future branch uses the same sampling semantics before treating it as native proof.
- `source.ts`: `QuadraticSourceBuilder`. Reuse only for the source-begin configuration/classes actually observed in the Bézier mode; do not assume the setting affects only final output.
- `reference.ts`: `convertPostSettings` already carries the native `selector482` field and zoom/tolerance arithmetic. Shared scalar equations are reusable after branch-specific caller arguments are established.
- `core.ts`: 10,000 input packets, 800 ms total arithmetic deadline, 1,000,000 source checks shared across groups, 10,000 expanded nodes shared across groups, 50,000 output points. It checks elapsed time while constructing source, between passes, and while sampling segments.
- `validation.ts`: `MAX_POST_POINTS = 50000`; all position, width, and elapsed time fields must be finite, widths/time nonnegative, time nondecreasing, and points stored as complete groups of four.
- `service.ts`: one disposable worker per request, 1,000 ms including startup/message transfer, immediate termination on cancellation. Deadline failure retains original ink and surfaces a persistent error through `inkEngine.ts`.
- `transferStrokeAttributes` remains a Croquis adaptation: transfer rendered width and elapsed time by normalized distance. Keep the explicit scaled-distance arithmetic that resolved Chromium/WebKit rounding differences. It is not CSP's native brush renderer.
- Native source groups remain combined into one user stroke and undo operation. Preserve idle-release records, cancellation, and ordering on layers, export, Merge down, and sealing. A curve mode must not introduce additional commits.

## Capture and replay changes needed before claiming equivalence

The existing recorder can observe generic post entry arguments, but the complete replay contract is ordinary-specific. A future agent must first extend and test the contract; turning on CSP's checkbox and running the ordinary replay does not validate Bézier reconstruction.

1. `spikes/live-capture/capture_post_correction.py` captures `k`, `flag480`, `closedMode`, `selector482`, tolerance, and length scale at the shared wrapper. Preserve raw arguments, path headers, node classes, stored controls, adjacency, endpoint bytes, evaluator configuration, and observed FPCR zero in the Bézier captures.
2. `spikes/live-capture/capture_joined_post.py` pins source begin/append/finish entry addresses and caller slices for the ordinary brush. Its verified ranges are the full begin/append/finish/wrapper plus specific caller slices. Establish whether Bézier uses these exact boundaries, primary holders, and source classes; if any differ, add mode-specific addressed assertions. Do not relax caller or image checks globally. Maintain the four-hardware-breakpoint limit and entry/return pairing.
3. `spikes/post-joined/source-replay.ts` currently requires begin uint32 `+0xd8 === 0`, with error “Source replay only supports ordinary open quadratic construction.” It restricts source caller returns to begin `0x10288ad38`, append `0x10288dda0` / `0x10288e2d8`, finish `0x102891848`. Keep ordinary checks and add the proven mode's explicit supported contract.
4. `spikes/post-pipeline/replay.ts`, `decodePostCapture`, requires source classes `PWVectorBezierCurve` with one control and all result classes `PWVectorSplineCurve`. Its comparison hard-codes spline class and compares ordinary node fields. Extend decoding/dispatch/comparison to the observed Bézier output class and every stored control field, using exact binary64 comparison for controls/coordinates and binary32 for retained scalars.
5. Production `pipeline.ts`, `runOrdinaryPostBeforeEndpoints`, expressly rejects `selector482 !== 0`, `closedMode !== 0`, quadratic source flags outside `(pathFlags & 0xf0) === 0x20`, or flag `0x100`. These guards remain correct for ordinary correction; build a Bézier routine instead of bypassing them.
6. Keep input source replay independent of the expected result. Expected controls, node counts, replacement order, and output flags are comparison targets only. Missing evaluator/caller/configuration observations must remain incomplete, not matched.
7. Require successful owned breakpoint cleanup, detach, and independent process-resume confirmation for every accepted capture. Debugger pauses prevent these captures from validating natural speed/latency.

The existing launcher `spikes/live-capture/record_joined_post.py` declares device mouse/tablet/unknown, saves unique persistent evidence, and speaks only after actual probe installation. It allows 45 seconds setup and a separate 45 seconds after the armed marker; the inner recorder has a 30-second inspection and 256-source-call bound. It does not synthesize input. These bounds and complete-failure reporting must be preserved when extending it. Prefer autonomous mouse captures once the mode-specific contract is proven; reserve operator tablet input for actual varying-pressure behavior.
